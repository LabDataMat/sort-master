# 收纳大作战 Sort Master（Phaser 3 版）

2D 休闲收纳消除游戏，纯浏览器运行。

**核心规则**：收纳槽中**任意三个相同物品即消除，不要求相邻、不要求连续点击**。

- 在线试玩：https://labdatamat.github.io/sort-master/
- 技术栈：Phaser 3 + TypeScript + Vite
- 关卡：100 关，数据驱动，全部通过可解性验证

## 四、核心玩法实现

`MatchSystem.resolveMatches` 以 `Map<itemId, SlotItem[]>` 分组计数：

| 场景 | 结果 |
|---|---|
| `A,B,A,C,A` | 三个 A 消除，剩余 `B,C`（**不相邻**） |
| `A,B,A` | 不消除 |
| `A,A,A,A` | 消除 3 个，剩余 1 个 |
| `A×6` | 两组消除 |
| `A,A,A,B,B,B` | 两组分别消除 |

- 消除后其余物品保持原有相对顺序；
- 物品一旦移除即不再参与匹配，机制上杜绝重复消除；
- `MatchSystem` / `SlotManager` 不依赖 Phaser，可独立测试。

遮挡规则：层号大者在上，同层时索引大者在上；两物品矩形宽高重叠均达到较小边的 35% 才算遮挡；被遮挡物品不可点击，上层移除后自动解锁。

## 五、关卡数据与转换

旧项目 `F:\Game3.0` 的关卡 JSON 只含**规格参数**（物品数、类型数、层数、半径等），坐标由旧项目运行时生成器产出，不能直接复制。

转换脚本 `scripts/convert-levels.mjs`：

1. 读取旧项目规格；
2. 调用旧项目生成器按固定种子生成布局；
3. 用**本项目规则**完整模拟（遮挡 → 拾取 → 计数式三消 → 容量 7 → 冰冻/锁定）；
4. 验证通过后写出 `public/levels/level_XXX.json`。

```bash
npm run convert
```

当前数据：100 关、约 1.2 万件物品、层数 2~7，**100/100 通过可解性验证**。

难度采用**断层设计**（`scripts/build-levels.mjs`）：

| 区间 | 设计 |
|---|---|
| 第 1 关 | 9 件 / 3 类 / 1 层 / 无遮挡 / 全部可点，难度 **1.0**，教学提示 |
| 第 2 关 | 90 件 / 11 类 / 6 层 / 420 条遮挡边 / 仅 10 件可点 / 道具 1 次，难度 **8.8** |
| 3~5 关 | 冰冻物品、有限道具、遮挡结构变化 |
| 6~20 关 | 隐藏物品、锁链、减容（6 格）、特殊挑战 |
| 21~100 关 | 混合难度：高难、限容、隐藏、收藏挑战 |

生成后用内置求解器（含遮挡、冰冻、锁链、隐藏、减容约束）验证，并计算 1~10 难度分。

## 七、构建与部署

```bash
npm run build      # 产物 dist/（约 6.6MB，含图片/音频/关卡）
```

部署由 `.github/workflows/pages.yml` 自动完成：

1. 检出仓库；
2. `npm ci` 安装依赖；
3. `npm test` 运行测试（失败则终止）；
4. `npm run build` 构建；
5. 上传 `phaser-game/dist` 并部署到 GitHub Pages。

支持 `workflow_dispatch` 手动触发。所有资源使用 `import.meta.env.BASE_URL` 前缀，兼容 `https://labdatamat.github.io/sort-master/` 子路径。

## 八、适配与性能

- 设计分辨率 750×1334，`Phaser.Scale.FIT` 等比缩放并居中，适配 PC 与移动端；
- 指针事件统一处理鼠标与触屏；
- 启动只预加载 30 物品 + 21 UI + 11 音频；关卡 JSON 进入关卡时按需 `fetch`；
- Phaser 单独分包（gzip 约 340KB），业务代码约 9KB（gzip）；
- 粒子与 Tween 数量受控，无逐帧对象创建。

## 九、说明

- 存档键：`sort_master_phaser_v1`（localStorage），刷新/关闭浏览器后保留。
- 音频在移动端需首次交互后解锁，已在首次指针事件中处理。
- `npm install` 使用国内镜像（`.npmrc`）；`package-lock.json` 已规范化为官方源地址，CI 可直接 `npm ci`。

## 十、收藏 / 奖励 / 经济系统

### 收藏品

- **48 件**收藏品，4 个系列各 12 件：美食、动物、生活用品、节日。
- 稀有度：每系列 6 普通 / 3 稀有 / 2 史诗 / 1 传说。
- 每件包含：唯一 ID、名称、图片、系列、稀有度、描述、获取条件、是否解锁。
- 图鉴中未解锁项显示**剪影 + 锁**，名称显示为 `???`；点击可查看详情与获取条件。

### 获取规则

| 来源 | 掉落 |
|---|---|
| 第 1 关首次通关 | **必定**获得 `food_01`（樱桃蛋糕） |
| 普通关卡 | 50% 概率普通收藏 |
| 高难关卡（难度 ≥ 7 / tier=hard） | 65% 概率稀有 |
| 特殊挑战（tier=challenge） | 40% 史诗、12% 传说 |

- 已拥有的收藏**不重复计入图鉴**，自动折算金币（普通 20 / 稀有 50 / 史诗 120 / 传说 300）。
- 集齐一个系列后可领取 **200 金币**，并播放庆祝动画；每个系列只能领取一次。

### 金币

| 用途 | 价格 |
|---|---|
| 撤回道具 | 60 |
| 提示道具 | 80 |
| 洗牌道具 | 100 |
| 暖阳桌面 | 300 |
| 夜色桌面 | 500 |

通关金币 = 档位基础（普通 10 / 高难 30 / 挑战 60）+ 首通 50 + 连胜加成（每层 5，上限 25）+ 重复折算。

### 其他

- **每日挑战**：主菜单入口，每天一次，通关额外 +50 金币。
- **连胜**：连续通关累计，失败清零，主页显示当前与最佳连胜。
- **难度标识**：关卡选择格显示难度分，游戏内顶栏显示 `难度 x.x · 档位`。
- 所有数值集中在 `src/core/RewardConfig.ts`，逻辑层不散落硬编码。
- 系统边界：`CollectionManager`（收藏）与 `RewardService`（奖励）只依赖 `SaveManager`，与渲染层解耦。
